Data Flow — a filtered dashboard request

1
User changes a dropdown in FilterBar.vue (Time Period, Location, Category, Order Status).
2
The useFilters composable holds all four values as shared refs (singleton). getCurrentFilters() maps them to { warehouse, category, status, month }.
3
The active view (e.g. Dashboard.vue) watches the filters and calls api.getDashboardSummary(filters).
4
api.js builds a URLSearchParams query string (dropping 'all') and issues GET http://localhost:8001/api/dashboard/summary?… via Axios.
5
FastAPI handler in main.py runs apply_filters() then filter_by_month() over the in-memory Python lists, and computes the summary numbers.
6
The response passes through the Pydantic response_model (where declared), is serialized to JSON, and returned with permissive CORS headers.
7
The view stores raw results in refs; computed properties derive display values (charts, KPI cards). Vue re-renders.

Notes & Observations

  • No database or persistence layer. All data is read from server/data/*.json into module-level lists at startup. Nothing written back survives a restart.
  • CORS is wide open (allow_origins=["*"]) — fine for a local demo, not for production.
  • Client references endpoints the backend does not implement: api.js defines getTasks, createTask, toggleTask, deleteTask and createPurchaseOrder / getPurchaseOrderByBacklogItem, but main.py has no /api/tasks or /api/purchase-orders routes.
  • Filtering is string-in based. filter_by_month matches on substrings of order_date; month/quarter logic lives in both main.py helpers and the /api/reports/* handlers.
  • This app has intentionally planted bugs for the workshop exercises.
